# PhysX 差速底盘接触与驱动排查经验

适用：Isaac Sim / IsaacLab 中，接触地面后轮速或车体运动出现偏置、低速粘滞、采样抖动；尤其是隐式速度驱动、很小的轮子惯量和多点刚性支撑的组合。以下内容来自 Emma 的实测，不构成所有机器人通用的参数配方。

## 先把测量做对

1. 用物理步长计时和采样，分别记录指令、报告轮速、关节角、根姿态和车体速度。若控制 decimation=2，同时比较奇偶物理步；50 Hz 数据可能只看见 100 Hz 仿真的一个相位。
2. 对关节角和 yaw 去回绕，再求差分。报告速度不必等于位姿变化率；不能只用报告轮速计算滑移率。对应官方解释见 [PhysX 5.4.1 solver iterations](https://nvidia-omniverse.github.io/PhysX/physx/5.4.1/docs/RigidBodyDynamics.html#solver-iterations)。
3. 同时保存车体和轮子的标准差。轮子速度高频摆动，不等于车体同等摆动；小标准差也不证明单步约束求解准确。
4. 静止整定后再发指令，分开评价启动、持续加速、反转、稳定速度。不要把放置/落地的瞬时冲量当作电机持续能力。
5. 固定“仿真时间窗”，不要固定“最后多少点”后跨采样率比较。检查提前终止、随机重置、障碍和目标触发；移动障碍物不一定关闭基于 LiDAR 的终止条件。

## 先核实模型，再调增益

- “只有 Y 轴转动”的被动轮不是万向脚轮。原地转向时，x≠0 的脚轮有横向速度 `omega_z*x`，必须擦地。应对照真机转向轴、拖距、预载和悬挂结构。
- 底盘水平、root_z 恒定，不能证明驱动轮承载正常。检查各支撑点的报告法向力、总重量平衡和载荷波动；并保留报告力不能代表每个内部子步的限制。
- 多个刚性接触点近乎共面时，小的高度差会大幅改变载荷分配。Emma 脚轮半径减少 0.5 mm 就让重量从脚轮转移到驱动轮。不能把该尺寸无依据地推广到其他车。
- 小轮惯量与高增益隐式驱动、接触约束会强烈耦合。armature 可改善数值行为，但会改变等效惯性；需要电机/减速器反射惯量依据，不能当作免费的稳定开关。
- 保留可见几何，用独立碰撞代理试验接触形状；不要为修正接触直接替换整个可见资产或破坏原有质量、惯量和关节。

## 不要误读执行器与材质接口

- `get_dof_actuation_forces()` 是外加 effort 输入缓冲，不是隐式速度电机总输出的独立测量。对应 `ImplicitActuator.applied_effort/applied_torque` 也可能是由 PD 误差计算的近似遥测。
- 恒定速度指令下，P-only 在轮子静止时不积累积分误差。用 `effort_limit/damping` 做饱和数量级检查；但不能用步末报告速度直接反推每个隐式子步的实际电机力矩。
- 同时读 composed USD 和运行时 tensor。运行时 IsaacLab 可能覆盖 USD 的 drive 增益、上限；只读资产文件容易误判。
- PhysX 扩展属性应通过对应 API schema 应用和设置。仅存在一个裸 `physxMaterial:*` 属性，不代表后端接受了它。
- 材质合成模式按优先级选取：`average < min < multiply < max`。正确生效的 min 不会被另一个材质的 average 覆盖。两侧都显式设 min 可以表达一致意图，但“必须两侧设 min 才生效”不是 PhysX 规则。[官方 PxCombineMode](https://nvidia-omniverse.github.io/PhysX/physx/5.1.0/_build/physx/latest/struct_px_combine_mode.html)

## 用可证伪的对照定位

- 先重现基线，再一次改一个参数；修复组合应回头测单项效果。
- 增加 pos_iters 有效，不等于唯一根因就是迭代数。TGS 的位置迭代还改变内部时间推进；稳定偏置可以是有限迭代离散系统的稳定状态。
- 外力每迭代选项在 Emma 原几何上恶化，在修改接触几何后改善。不能把一次成功转换成全局默认经验。
- 降 damping、换 PGS、改 CFM、contactSlop 或 friction correlation 都应该以数据决定。在本次原几何低速对照中它们没有解决问题。
- 大标准差不等于发散；检查振幅/能量是否持续增长。也不要只凭低速更差就确认经典静动摩擦 stick-slip。

## 落地时保留边界

- 指令加速度限幅不是车体实际加速度的数学保证。记录实际起步和反转峰值；碰撞、安全制动、初始整定和负载变化需要单独评价。
- 安全盾应看到限幅后的名义指令；安全制动/急停不能被平滑器重新混入旧高速指令。
- 增加状态缓冲后，测试按环境重置，避免上一回合的目标泄漏到新回合。
- 多环境仿真要验证首尾环境的碰撞代理和材质都完成复制。测试 1 个环境不足以证明 1024 环境配置一致。
- 吞吐使用同一机器、同类动作、相同环境数做相邻 A/B；记录共享 GPU 负载。不要拿两次不同时间、不同探针的数字声称精确收益。
- 先备份用户已有改动，再做定点修改。保存探针、机器可读时序、当时的参数和失败对照。注释中只保留当前结论，历史解释放在有日期的调查记录里。
